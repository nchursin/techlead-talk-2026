# TDD Presentation — Style & Narrative Guide

Typst-презентация «Разрушители мифов: TDD». Компиляция: `typst compile main.typ presentation.pdf`. Все слайды в `main.typ`, компоненты в `theme.typ`.

---

## Нарративная архитектура

### Центральный приём: виртуальный спор

Вся презентация — диалог с собирательным образом скептика. Каждый миф оформляется как возражение оппонента (`#objection`), за которым следует ответ на `#slide`. Это не лекция — дебаты.

**Структура секции мифа:**
```
#objection([Возражение оппонента], [Опциональное уточнение или пустой []])
→ один или несколько #slide с ответом (kicker называет миф)
```

### Общая дуга презентации

1. Открытие (`#hero` + слайд «Это я»)
2. Список всех мифов (`#progressive-slide` — все 8 сразу, поштучно)
3. Нарративный мост (image-слайд с котом — разрядка)
4. Секции мифов:
   - **Технические:** требования → время → все тесты сразу → переделки при смене направления → только unit-тесты → хрупкие тесты
   - Сводка «Что мы уже узнали о TDD»
   - **Организационные:** команда → менеджер (цифры) → легаси
   - **Современный контекст:** LLM (антипаттерн / тест как спека / YOLO)
   - Финал: серебряная пуля → что TDD не делает / что делает → неочевидные последствия
5. CTA «Будьте как Дима»

**Инвариант:** мифы в начальном `#progressive-slide` идут в той же последовательности, в которой раскрываются в теле. При добавлении нового мифа — обновить оба места.

## Slide Types

| Тип | Когда использовать | Визуальный маркер |
|-----|--------------------|-------------------|
| `#hero(title, subtitle)` | Открытие, крупные разделители | Teal-бар (2.8in), заголовок 32pt |
| `#slide(title, body, kicker:)` | Ответ на миф, контент | Purple-бар, kicker-чип опционально |
| `#objection(title, subtitle)` | Голос оппонента | Красный бар (2.8in), «кавычка» 60pt red |
| `#progressive-slide(title, items)` | Список независимых пунктов для поштучного раскрытия | Как `#slide`, создаёт N+1 слайдов |
| `#cheatsheet(title, body)` | Накапливаемая шпаргалка по TDD | Жёлтый бар, жёлтый заголовок, чип «Шпаргалка» встроен |

`#objection` — строго только голос оппонента. Никогда не использовать для авторских утверждений.

## Компоненты контента

### Карточки

**`#card(body)`** — базовый контейнер, фон `panel` (#121A31), 16pt скругления.

**`#card(body, fill-color: panel-soft)`** — светлее. Используется ТОЛЬКО для вывода/инсайта под основной карточкой:

```typst
#card([...основное содержимое...])
#v(0.14in)
#card([#text(size: 18pt)[Ключевой вывод одной строкой]], fill-color: panel-soft)
```

Это визуальное «вот суть». Применять экономно — 2–3 раза на всю презентацию.

### Лейаут

- **`#three-cols(a, b, c)`** — параллельные концепции одного уровня. Применяется для RED-GREEN-REFACTOR и «Неочевидных последствий».
- **`#two-cols(left, right)`** — процесс + иллюстрация.

### Kicker

`kicker:` на `#slide` — маленький чип (11pt, `accent-2` на `panel-soft`), называет миф или контекст. Формат: `[Миф: текст мифа]` или тематический лейбл (`[TDD и LLM]`, `[Как продать менеджеру]`). Один kicker держится на всех слайдах одной секции.

## Голос и тон

**Язык:** Разговорный русский, обращение на «ты». Технически точный, но не академический. Без канцелярита.

**Буллеты:** Короткие, ёмкие. Предпочтительны императивная или назывная формы:
- `Написать тест` — не «Необходимо написать тест»
- `Скрытое допущение: «ты написал много тестов заранее»`
- `Хрупкость = тест знает про реализацию, не про поведение`

**Голос возражений (`#objection`):** Первое лицо оппонента, разговорно. Многоточия, восклицания уместны. Должно звучать как живые слова реального разработчика.

**Голос ответных слайдов:** Диагностический, объясняющий, переформулирующий. Часто начинается с «скрытого допущения» или переопределения термина.

**Определения:** Вводить явно на том же слайде через тире:
`*Легаси* — не «старый код», а «код, который страшно менять»`

**Сильные утверждения:** Формулировать как диагноз:
`«Хрупкость — диагноз, не приговор TDD»`

## Структурные паттерны

**Callback-петля:** Мифы перечислены в начальном `#progressive-slide` → каждый адресуется в теле с `kicker` → финальные `#progressive-slide` закрывают петлю.

**Процесс через одинаковые заголовки:** Сложный процесс показывается серией слайдов с одним заголовком — каждый добавляет один шаг. Визуально моделирует инкрементальный TDD-подход.

**Визуальные мосты:** Image-слайды без объяснений (кот, мем с титаником) — намеренные паузы-разрядки между тяжёлыми секциями.

**Negation + Affirmation:** «Что TDD НЕ делает» → сразу «Что TDD делает на самом деле». Всегда парой, никогда по отдельности.

**CTA через персонажа:** Финал — конкретный человек («Будь как Дима») + обещание практики, не абстрактный призыв к ценностям.

**Шпаргалка (накапливаемый референс):** `#cheatsheet` появляется в конце каждой секции мифа и накапливает шаги TDD. Использовать строго с заголовком «Как делать TDD», тело — нумерованный список в `#card`.
